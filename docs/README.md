# XYO Version — Documentation

`xyo-version` keeps the version numbers of a project in a small JSON file
(`version.json`) and puts them into the sources at build time. It is both:

- **a command line tool**, `xyo-version`, used by
  [fabricare](https://github.com/g-stefan/fabricare) (`fabricare version`)
  in every XYO C++ project: bump the build number, bump patch / minor / major, print
  the current version, and expand a `Version.Template.rh` into the
  `Version.rh` header that gives the library or executable its version
  string and its Windows `VERSIONINFO` resource;
- **a C++ library**, namespace `XYO::Version`, with the same operations as
  functions (`get`, `set`, `buildBump`, `patchBump`, `minorBump`,
  `majorBump`, `processTemplate`) plus two helpers for code that installs
  or updates packages: `compare` (order two `major.minor.patch` versions)
  and `specificity` (an npm semver range check: `^1.2.3`, `~1.2`,
  `>=1.2.7 <1.3.0`, `1.2.x || >=2`, `1.2.3 - 2.3.4`, ...).


## Why it exists

Every XYO library and executable reports its own version at run time
(`XYO::System::Version::version()`, `xyo-version --version`, the Windows
file properties dialog) and every build should be traceable to an exact
build number. Doing that by hand means editing a header and a resource
file in step for every build. `xyo-version` makes it one command:

| Problem | What `xyo-version` does |
|---------|-------------------------|
| The version lives in several places (header, `.rc` resource, package metadata) | One `version.json` per repository is the single source; headers are generated from templates |
| Every build should get a distinct number | `--bump` (`fabricare version`) increments `build` and stamps `date` / `time` |
| A Windows `VERSIONINFO` needs `a,b,c,d`, C++ code needs `"a.b.c"` | `#{VERSION_ABCD}` and `#{VERSION_VERSION}` are expanded from the same entry |
| One repository builds several binaries (a DLL and an exe with the same name) | `version.json` holds one entry per project name; fabricare `versionName` / `linkVersion` choose which one |
| An installer must decide if an installed package satisfies `^1.2.3` | `XYO::Version::specificity(installed, range)` |

## Concepts at a glance

| Need | Command line | Library |
|------|--------------|---------|
| Print the version of a project | `xyo-version --project=name --get` | `XYO::Version::get(file, name)` |
| Create a project entry / set a version | first `--bump` on a new name creates `0.0.0` build `0` | `XYO::Version::set(file, name, "1.0.0")` |
| Next build | `--bump` or `--bump-build` | `buildBump(file, name)` |
| Next patch / minor / major | `--bump-patch`, `--bump-minor`, `--bump-major` | `patchBump`, `minorBump`, `majorBump` |
| Generate a header from a template | `--file-in=Version.Template.rh --file-out=Version.rh` | `processTemplate(file, name, in, out)` |
| Order two versions | | `XYO::Version::compare("1.2.3", "1.10.0")` |
| Does an installed version satisfy a range | | `XYO::Version::specificity("1.4.0", "^1.2.3")` (`true` = needs update) |
